## Модель

Иерархия студентов:

```text
Student
├── BudgetStudent
├── PaidStudent
└── ForeignStudent   (дополнительное задание)
```

- `Student` хранит общие данные: имя и список курсов.
- `BudgetStudent` добавляет стипендию.
- `PaidStudent` добавляет плату за обучение.
- `ForeignStudent` добавляет страну и имеет фиксированную плату `300000`.

`Course` хранит:

- темы — композиция;
- указатель на профессора — агрегация;
- список студентов `std::vector<Student*>` — агрегация.

## Наследование

- наследование публичное: `class BudgetStudent : public Student`;
- конструкторы производных классов вызывают `Student(name)` в списке инициализации;
- общие поля `name_` и `courses_` находятся только в `Student`;
- поля `scholarship_`, `tuition_`, `country_` находятся только в соответствующих наследниках;
- `virtual` и `override` для обычных методов в этой работе не используются;
- деструктор базового класса объявлен `virtual ~Student() = default;` — это правильная основа для следующей работы, где удаление через базовый указатель станет важным.

## Агрегация студентов в Course

`Course` хранит `std::vector<Student*> students_`, но не владеет студентами. В `Course::enrollStudent` есть проверки:

- `nullptr` не добавляется;
- повторная запись того же указателя игнорируется;
- деструктор `Course` не удаляет студентов.

В `main` нет `new` и `delete`, все объекты создаются на стеке.

## Демонстрация

Программа:

1. Создаёт профессоров, курсы и четырёх студентов.
2. Записывает студентов на курсы двумя способами:
   - `student.enroll(&course)`;
   - `course.enrollStudent(&student)`.
3. Проверяет защиту от дубликатов.
4. Выводит студентов, их курсы, курсы с темами и списками студентов.
5. Считает общую плату вручную через конкретные объекты.
6. Выводит стипендии бюджетников.
7. Показывает работу невиртуальных методов через `Student*`.

## Важное замечание о невиртуальных методах

В этой работе `getStatus()`, `getTuition()` и `getScholarship()` объявлены **не виртуальными**. Поэтому вызов через `Student*` использует версию базового класса:

```text
Alice: status=Student, tuition=0, scholarship=0
Bob:   status=Student, tuition=0, scholarship=0
...
```

Чтобы получить корректные статус, плату и стипендию в основной части программы, используются вызовы через конкретные объекты:

```cpp
alice.getStatus();
bob.getTuition();
alice.getScholarship();
```

Именно это демонстрирует ограничение статического связывания. В работе №7 методы нужно будет сделать виртуальными, чтобы вызовы через `Student*` работали полиморфно.

## Эксперимент 1

Если в `Student` нет метода `getScholarship()`, а он объявлен только в `BudgetStudent`, то код

```cpp
Student* s = &alice;
s->getScholarship();
```

не компилируется:

```text
'class Student' has no member named 'getScholarship'
```

Компилятор смотрит на статический тип указателя `Student*`, а не на реальный объект `BudgetStudent`. Поэтому метод, которого нет в базовом классе, через базовый указатель недоступен.

## Эксперимент 2

После добавления `getScholarship()` в `Student`:

```cpp
int Student::getScholarship() const { return 0; }
```

код компилируется, но через `Student*` вызывается именно `Student::getScholarship()` и возвращается `0`, а не `1500` у `BudgetStudent`. Это происходит потому, что метод не виртуальный.

Чтобы вернуть правильное значение, нужно:

- сделать метод виртуальным (тема работы №7);
- либо вызывать его через указатель/ссылку конкретного типа `BudgetStudent*` / `BudgetStudent&`;
- либо обращаться к конкретному объекту `alice`.

## Контрольные вопросы

1. **Почему `name_` объявлено в `Student`, а не дублируется в наследниках?**  
   Имя есть у всех студентов. Общее поле должно храниться в базовом классе, чтобы не дублировать код и данные.

2. **Почему `scholarship_` только в `BudgetStudent`, а `tuition_` только в `PaidStudent`?**  
   Эти поля относятся только к конкретным видам студентов. Если объявить оба поля в `Student`, базовый класс будет знать о деталях наследников, а у части объектов появятся бессмысленные поля.

3. **Что будет, если в конструкторе `PaidStudent` не вызвать `Student(name)`?**  
   Компилятор попытается вызвать конструктор `Student()` по умолчанию. Такого конструктора нет, поэтому будет ошибка компиляции.

4. **Почему `getTuition()` в `PaidStudent` возвращает `tuition_`, а в `BudgetStudent` — `0`?**  
   `PaidStudent` переопределяет метод и возвращает своё поле. `BudgetStudent` не переопределяет `getTuition()`, поэтому наследует `Student::getTuition()`, который возвращает `0`. Поле платы у бюджетника не хранится.

5. **Почему `getScholarship()` в `BudgetStudent` возвращает `scholarship_`, а в `PaidStudent` — `0`?**  
   `BudgetStudent` переопределяет метод. `PaidStudent` наследует `Student::getScholarship()`, который возвращает `0`. Поля стипендии у платника нет.

6. **Можно ли объявить `std::vector<Student> students` в `Course`?**  
   Нельзя хранить наследников по значению: произойдёт срезка объекта (`object slicing`). В векторе останется только часть `Student`, поля `tuition_`, `scholarship_`, `country_` потеряются. Нужен `std::vector<Student*>` или контейнер умных указателей.

7. **Почему в `Course.h` достаточно `class Student;`, а в `Course.cpp` нужен `#include "Student.h"`?**  
   В заголовке хранится только указатель, для которого достаточно неполного типа. Полное определение нужно в `.cpp`, когда используются методы или размер объекта.

8. **Почему `~Student()` виртуальный, хотя в этой работе нет удаления через базовый указатель?**  
   Это правильная практика для базового класса с наследниками. Если позже объект удалят через `Student*`, виртуальный деструктор обеспечит вызов деструктора наследника. В работе №7 это станет обязательным.

9. **Почему у бюджетника плата `0`, а у платника `200000`?**  
   В ручном подсчёте используются конкретные объекты: `bob.getTuition()` вызывает `PaidStudent::getTuition()`. Через `Student*` из-за отсутствия виртуальности вызвалась бы базовая версия и вернула `0` — это показано в эксперименте.

10. **Почему в эксперименте 1 нельзя вызвать `getScholarship()` через `Student*`?**  
    Компилятор проверяет статический тип `Student*`. Если в `Student` метода нет, вызов невозможен, даже если реальный объект — `BudgetStudent`.

11. **Почему в эксперименте 2 через `Student*` возвращается `0`, а не `1500`?**  
    Метод не виртуальный, поэтому вызывается `Student::getScholarship()`. Чтобы работало полиморфно, нужен `virtual` (работа №7) или вызов через конкретный тип.

## Дополнительное задание: ForeignStudent

`ForeignStudent`:

- наследует `Student`;
- хранит только `country_`;
- `getStatus()` возвращает `"Foreign"`;
- `getTuition()` возвращает фиксированную сумму `300000`;
- конструктор принимает имя и страну, без параметра платы.

В `main` иностранный студент записан на курс, отображается в списке студентов курса, а его плата `300000` учтена в ручном подсчёте общей платы.

### Почему `ForeignStudent` не дублирует `name_` и `courses_`

Эти поля общие для всех студентов и уже находятся в `Student`. Наследник получает их через наследование и не должен объявлять повторно.

### Почему `ForeignStudent` дублирует логику платы из `PaidStudent`

Оба класса возвращают фиксированную сумму, но хранят её по-разному: у `PaidStudent` есть поле `tuition_`, у `ForeignStudent` сумма задана константой. Общую логику можно вынести в базовый класс, если сделать `getTuition()` виртуальным и, например, хранить сумму в `Student` или сделать метод чисто виртуальным. В этой работе виртуальные методы ещё не используются, поэтому переопределение выглядит как дублирование.

## Итог

- наследование публичное;
- общие поля находятся в базовом классе;
- различающиеся поля — только в наследниках;
- конструкторы наследников вызывают конструктор базы;
- `Course` агрегирует студентов и не владеет ими;
- в `main` нет `new`/`delete`;
- программа собирается с `-Wall -Wextra` без предупреждений.
