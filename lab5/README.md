# Практическая работа №5. Агрегация и композиция

## Предметная область

Упрощённая модель учёта университетских курсов. В проекте три класса:

- `Professor` — профессор;
- `Course` — курс с темами и ссылкой на профессора;
- `Student` — студент, записанный на курсы.

## Типы связей

| Связь | Тип | Реализация |
|---|---|---|
| `Course` → `topics_` | Композиция | `std::vector<std::string>` как поле класса |
| `Course` → `Professor` | Агрегация | `Professor*` — курс не владеет профессором |
| `Student` → `Course` | Агрегация | `std::vector<Course*>` — студент не владеет курсами |

## Композиция тем курса

`Course` хранит темы в `std::vector<std::string> topics_`. Вектор является полем объекта, поэтому:

- темы создаются вместе с курсом;
- при уничтожении `Course` вектор автоматически уничтожает все строки;
- вручную вызывать `delete` не нужно;
- указателей на темы класс не хранит.

## Агрегация профессора

`Course` хранит `Professor* professor_`, но не создаёт и не удаляет профессора. Профессор может вести несколько курсов, поэтому курс не должен управлять временем его жизни.

В `Course.h` используется предварительное объявление:

```cpp
class Professor;
```

Полный `#include "Professor.h"` находится только в `Course.cpp`, потому что в заголовке достаточно указателя на неполный тип.

## Агрегация курсов у студента

`Student` хранит `std::vector<Course*> courses_`. Метод `enroll`:

- игнорирует `nullptr`;
- не добавляет один и тот же курс дважды;
- не удаляет курсы в деструкторе.

## Владение профессорами через контейнер

В `main` профессоры хранятся в контейнере:

```cpp
std::vector<std::unique_ptr<Professor>> professors;
```

`unique_ptr` является владельцем объекта и автоматически удаляет профессора при выходе из `main`. При этом `Course` по-прежнему хранит обычный указатель и не делает `delete`.

В `main` нет явных `new` и `delete`.

## Ответы на контрольные вопросы

1. **«Класс Course владеет полем topics_, потому что…»**  
   `topics_` является полем объекта `Course`. Время жизни вектора и его строк совпадает со временем жизни курса. При уничтожении курса вектор автоматически освобождает свои элементы.

2. **«Класс Course не владеет объектом Professor, потому что…»**  
   Профессор существует независимо от курса и может вести несколько курсов. Если курс удалит профессора, другие курсы получат висячие указатели. Владельцем профессора должен быть внешний объект: `main` или контейнер.

3. **Зачем в `Course.h` используется `class Professor;` вместо `#include "Professor.h"`?**  
   В заголовке достаточно знать, что существует класс `Professor`, так как хранится только указатель. Полное определение нужно лишь там, где вызываются методы профессора, — в `Course.cpp`. Это уменьшает зависимости и время компиляции.

4. **Что произойдёт, если в деструкторе `Course` написать `delete professor_;`?**  
   Курс удалит объект, которым не владеет. Если профессор создан на стеке, это приведёт к двойному удалению. Если он используется другими курсами, возникнут висячие указатели и неопределённое поведение.

5. **Почему в деструкторе `Student` нельзя удалять элементы `courses_`?**  
   Курсы принадлежат внешнему коду и могут быть общими для нескольких студентов. `Student` только ссылается на них, поэтому не должен управлять их временем жизни.

6. **В чём разница между композицией и агрегацией?**  
   При композиции владелец управляет временем жизни части: часть создаётся и уничтожается вместе с владельцем. При агрегации объект только ссылается на другой объект, а владелец находится снаружи.

## Дополнительное задание

### Константная ссылка на темы

Метод

```cpp
const std::vector<std::string>& getTopics() const;
```

возвращает константную ссылку. Это нужно, чтобы:

- не копировать вектор при каждом вызове;
- запретить изменение внутреннего списка тем через геттер;
- сохранить инкапсуляцию: менять темы можно только через `addTopic`.

### Контейнер-владелец профессоров

Выбран `std::vector<std::unique_ptr<Professor>>`, потому что:

- `unique_ptr` выражает единоличное владение;
- владельцем является контейнер;
- при выходе из `main` все профессоры удаляются автоматически;
- в `main` не нужно писать `new` и `delete`;
- `Course` хранит невладеющий указатель и не должен удалять профессора.
